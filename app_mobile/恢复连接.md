# 小车恢复连接

本文根据当前项目源码整理，用于小车仍在、但已经不知道如何联网和连接时恢复使用。

## 结论

- 手机端不会自动发现小车，只能连接“小车 IP + TCP 8010”。
- 小车使用 Android Things 系统联网，项目本身没有配网页面。
- 小车端 `MainActivity` 运行后才会启动 TCP 8010 服务。
- 摄像头预览另外使用 UDP 8000。
- 如果小车还记着以前的 Wi-Fi，它可能没有接入现在的局域网。

恢复连接的推荐顺序：

1. 小车通过网线接入当前路由器。
2. 从路由器后台取得小车 IP。
3. 测试 TCP 8010。
4. 如果 8010 未开放，通过 ADB 检查并启动小车应用。
5. 在 ADB 可用后，把小车改到现在的 Wi-Fi。
6. 手机填写小车 IP 和 8010 进行连接。

## 1. 先通过网线找回小车

这是恢复成功率最高的方法。

1. 给小车断电。
2. 用网线连接小车树莓派和当前路由器。
3. 给小车通电，等待约一分钟。
4. 打开路由器管理后台，查看新出现的有线设备。
5. 记下该设备的 IP 地址。

在电脑测试小车应用是否已经监听 8010：

```bash
nc -vz 小车IP 8010
```

如果提示连接成功，说明小车应用已经运行，可以直接跳到“手机连接”。

如果超时或拒绝连接，继续通过 ADB 检查。

## 2. 通过 ADB 接管小车

Android Things 通常允许通过局域网进行 ADB 调试。先尝试：

```bash
adb connect 小车IP:5555
adb devices -l
```

连接成功后确认设备型号：

```bash
adb -s 小车IP:5555 shell getprop ro.product.model
```

代码只在下面这个型号上初始化车轮、灯、蜂鸣器和舵机：

```text
iot_rpi3
```

如果返回其他型号，即使 TCP 能连接，硬件驱动也不会初始化。

## 3. 检查和启动小车应用

检查应用是否还安装着：

```bash
adb -s 小车IP:5555 shell pm list packages | grep org.mark.thingshello
```

如果输出：

```text
package:org.mark.thingshello
```

手动启动应用：

```bash
adb -s 小车IP:5555 shell am start -n org.mark.thingshello/.MainActivity
```

再次测试端口：

```bash
nc -vz 小车IP 8010
```

小车应用在 Manifest 中声明了 `IOT_LAUNCHER`，正常情况下开机应该启动；但旧系统恢复后，默认启动状态可能已经改变，所以需要手动验证。

## 4. 应用不在时重新安装

在项目根目录构建小车 APK：

```bash
./gradlew :app:assembleDebug
```

安装并启动：

```bash
adb -s 小车IP:5555 install -r app/build/outputs/apk/debug/app-debug.apk
adb -s 小车IP:5555 shell am start -n org.mark.thingshello/.MainActivity
```

然后测试：

```bash
nc -vz 小车IP 8010
```

## 5. 把小车连接到现在的 Wi-Fi

源码的 `DeviceManager` 注释中保留了 Android Things 的系统配网方式。先通过网线建立 ADB 连接，再执行：

```bash
adb -s 小车IP:5555 shell am startservice \
  -n com.google.wifisetup/.WifiSetupService \
  -a WifiSetupService.Connect \
  -e ssid '你的WiFi名称' \
  -e passphrase '你的WiFi密码'
```

等待约 20 秒，然后：

1. 拔掉网线。
2. 重启小车。
3. 到路由器后台查找小车新的无线 IP。
4. 使用新 IP 再测试 8010。

```bash
nc -vz 新的小车IP 8010
```

注意：无线和有线连接通常会获得不同 IP。

## 6. 手机连接

手机和小车需要处于同一个可互通的局域网。

打开 `app_mobile`：

1. 在 `host ip address` 输入小车 IP，而不是手机 IP。
2. 端口保持 `8010`。
3. 打开旁边的连接开关。
4. 等待日志显示 `Status:CONNECTED`。
5. 点击启用后的 `Ctrl`。

如果能够控制车轮但没有画面，TCP 已经正常，应继续检查 UDP 8000 和摄像头。

## 7. 无法连接时检查

### 手机一直无法连接

依次确认：

- 手机和小车是否连接同一个路由器。
- 路由器是否开启了 AP 隔离或访客网络隔离。
- 填写的是否是小车当前 IP。
- 手机端口是否保持 8010。
- 小车端 `org.mark.thingshello/.MainActivity` 是否正在运行。
- 电脑执行 `nc -vz 小车IP 8010` 是否成功。

### ADB 无法连接 5555

- 确认小车确实已经通过网线获得 IP。
- 尝试通过路由器设备列表核对 MAC 地址和连接类型。
- 如果设备提供 USB 调试接口，可连接电脑后执行 `adb devices -l`。
- 如果 ADB 和 8010 都无法访问，可能需要重新烧录 Android Things 系统。

重新烧录会清除小车系统和已安装应用，应在确认其他连接方式都失败后再做。

### 已连接但硬件完全不动

检查：

```bash
adb -s 小车IP:5555 shell getprop ro.product.model
```

必须返回 `iot_rpi3` 才会执行当前项目里的硬件初始化代码。还要检查电机独立供电和 GPIO 接线。

### 能驾驶但预览黑屏

摄像头流程使用两个端口：

| 端口 | 用途 |
| --- | --- |
| TCP 8010 | 手机发送摄像头打开、关闭等指令 |
| UDP 8000 | 手机发送预览握手，小车回传图像 |

检查路由器是否阻止设备间 UDP 通信，并查看小车日志中的 `DoorbellCamera`、`CameraService` 和 `UdpSender`。

## 8. 安全提示

当前代码没有实现手机断线自动停车。手机断网或应用退出时，小车不一定立即收到停车指令。

第一次恢复使用时：

1. 先架空驱动轮。
2. 使用较低速度测试。
3. 确认松开摇杆和转向按钮后车轮停止。
4. 退出前主动停车，再关闭手机端连接开关。

不要用断开 Wi-Fi 代替停车。

## 9. 源码依据

- 小车 TCP 8010：`lib_unit_socket/SocketManager.java`
- 手机默认端口 8010：`app_mobile/src/main/res/layout/activity_main.xml`
- 摄像头 UDP 8000：`app/src/main/java/org/mark/thingshello/video/sender/UdpSender.java`
- Android Things Wi-Fi 配网命令：`app/src/main/java/org/mark/thingshello/ctrl/DeviceManager.java`
- `iot_rpi3` 硬件初始化判断：`app/src/main/java/org/mark/thingshello/ctrl/DeviceManager.java`
- 小车启动入口：`app/src/main/java/org/mark/thingshello/MainActivity.java`
